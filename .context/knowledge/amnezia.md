- Fallback protocol research (2026-09-07): [AmneziaWG docs](https://docs.amnezia.org/documentation/amnezia-wg/) describe UDP transport and now include version 3.1, while some linked self-hosted instructions still refer to 2.0. Before adding a fallback, verify the installer and actual macOS/iOS client versions support the same protocol generation; do not select 2.0 from an older link title or assume profiles are interchangeable. [Current FAQ](https://docs.amnezia.org/faq/). Local UAE reachability remains untested for this candidate.
- Shared-host source inspection (5.0.1.5): `client/server_scripts/xray/run_container.sh` publishes the selected port on both TCP/UDP without a host-IP binding; `awg/run_container.sh` publishes UDP similarly. Both join `amnezia-dns-net`; AWG's `start.sh` masquerades tunnel traffic through eth0/eth1. Two EIPs alone will not yield isolated ingress/egress. See [architecture candidate](../../docs/architecture.md#selected-topology) before planning consolidation.
- Runtime extraction: tagged `server_scripts/xray/Dockerfile` pins Xray `v26.7.28` but downloads without a checksum check; AWG's Dockerfile uses `amneziavpn/amneziawg-go:latest`. Both upgrade packages and create a placeholder startup script for subsequent injection. Xray `start.sh` can reach `tail -f /dev/null` after daemon exit, while AWG configuration generates keys during setup. Our lifecycle must make process failure visible and preserve credentials on repeat deployment. Preserve source/license provenance when adapting recipes; upstream root README identifies GPLv3 and separate third-party terms.

## Owned runtime learnings (2026-09-07)

- The reference Xray directory has six flat files, including `server.json` with two clients and `clientsTable`. There is no running DNS sidecar or explicit server DNS config; preserve all bytes rather than regenerating a single-client template. The protected local bundle is `.local/recovery/cape-town-runtime.json`.
- Host Ubuntu and container Alpine versions are separate. Keep Ubuntu 24.04 and the inspected upstream container family during migration. Runtime pins and licensing are in `runtime/NOTICE.md`.
- This Ubuntu AMI already renders EC2 secondary IPv4 addresses in cloud-init netplan. Bootstrap verifies it; a redundant overlay was removed before cutover. DHCP provides the primary address/default route.
- Docker's `com.docker.network.host_ipv4` produced an actual kernel `SNAT --to-source` rule. Verified Xray container egress equals the existing EIP after reassociation. Inspect the rule and external IP, not just Compose text.
- AWG's userspace control socket is `/run/amneziawg/awg0.sock`, not `/run/wireguard`. The daemon advertises an old version string even though the pinned image's tools accept generated 3.1 settings. Disposable-container startup/restart tests verify the actual integration. Keep it unprivileged except TUN/NET_ADMIN.
- Docker Desktop's containerd image ID can be an index digest, while another host uses a different image identity representation. Transfer and reference a build-input-hash tag with pulling disabled; do not assume the local `.Id` is a portable remote image reference. ECR release management remains deferred.
- Secret diagnostics: catch JSON parser errors without quoting input; capture SSH/command output privately. Real server configuration should never reach tool output. Normal runtime logging stays disabled.

- AWG client import (5.0.1.5): `importController.cpp` accepts native `[Interface]`/`[Peer]` config and recognizes 3.1 keys. Text `vpn://` import is base64url of Qt qCompress (4-byte big-endian original UTF-8 length plus zlib). QR import accepts raw native config; compressed native text follows a different parser path and must not be assumed equivalent. Use `runtime ... share awg`; no server-admin credentials are included.
- Mac `.vpn` import succeeded through plus → File with connection settings, showing AmneziaWG version 3.1. A native file picker may display a selected file but ignore confirmation while unfocused: raise AmneziaVPN through CUA's exposed window Raise action, then refresh its state before confirming. Do not infer unsupported format from the disabled-looking picker alone.
- Retiring the old host exposed AWS KeyPair tag replacement semantics. Preserve its existing System=xray tag and logical ID; managed host/disk/network billing tags are already shared. The one-time migration-stage API is removed after retirement.

- Mac installation archives must set `COPYFILE_DISABLE=1`; otherwise tar adds `._*` AppleDouble files to the server config directory and complete export fails basename validation. The archive helper/test covers real xattrs. Clean already-uploaded sidecars only after verifying AppleDouble magic `00051607`; never weaken export validation or discard arbitrary hidden files.

- Final Apple trial: Anthony confirmed iPhone AWG import/practical/manual-switch and Mac post-reboot AWG reconnect passed on 2026-09-07. The local profile-sharing workflow is validated; do not mistake the Qt radio-selection automation limitation for a protocol failure.

## Invisible macOS window (2026-09-07)

- Observed AmneziaVPN 5.0.1 build 5 on macOS 26.6.2: GUI/service processes running, Command-Tab activates the application, but no usable window; reinstall and OS restart did not help. Process sampling showed a normal idle event loop, and `org.amneziavpn.AmneziaVPN` had `Conf.startMinimized=true`. This matches the older upstream [start-minimized window issue #412](https://github.com/amnezia-vpn/amnezia-client/issues/412); do not assume a damaged installation.
- Successful recovery: export both preference domains to protected local backup files, stop only the GUI process, run `defaults write org.amneziavpn.AmneziaVPN Conf.startMinimized -bool false`, then relaunch normally. Source `amneziaApplication.cpp` invokes `showOnStartup` on macOS. Leave profiles, Keychain and helper service intact; avoid a full preference reset/uninstall.
- Verified a visible responsive window, both Cape Town REALITY/AWG profiles, disabled startup setting, and byte-identical encrypted `Servers.serversList` plus unchanged default profile identity. No VPN connection or server change was needed. Local backups/sample are under `.local/diagnostics/amnezia-window/`, directory 700/files 600; these are machine-local recovery aids, not independent Keychain backups.

## Fresh-region / lifecycle learnings (2026-09-09)

- `client/core/controllers/selfhosted/importController.cpp` recognizes `vless://` before generic JSON/compressed formats; `client/core/utils/serialization/vless.cpp` maps `pbk`, `sid`, `sni`, `fp`, `flow` and the display-name fragment. Ghostline uses this standard link for fresh Xray device imports/QRs; server settings mirror the pinned `server_scripts/xray/template.json` / configurator and live reference.
- EIP CloudFormation `PhysicalResourceId` is its public IPv4, not allocation ID. Match live stack resource addresses to the explicit allocation outputs before capturing a teardown record. Parked allocations keep CloudFormation and project/protocol tags; no orphan import is needed.
- Xray's image ENTRYPOINT includes the server config. A disposable client validation must override the entrypoint to `/usr/bin/xray` before selecting its client config, otherwise Xray tries to load both files.

## Guarded native Mac AWG tests (2026-09-09)

- Anthony authorized reconnecting AWG with automatic recovery after a reported loss of internet. Source `client/mozilla/localsocketcontroller.cpp` and `client/daemon/daemonlocalserverconnection.cpp` define newline-delimited JSON over `/var/run/amneziavpn/daemon.socket`: `{"type":"status"}` reports connection/endpoint/counters and `{"type":"deactivate"}` follows the app's normal disconnect path. A separate local watchdog can invoke it without internet or GUI access. This is an inspected internal API tied to Amnezia 5.0.1.5, not a stable public CLI.
- Verify the target is disconnected and the local disconnect action works before arming a test; use a separate unconditional timer as well as early failure detection. Always verify daemon disconnection and restored direct egress afterward. Avoid a toggle action that could accidentally reconnect after an owner disconnect.
- Task-local diagnostic script/artifacts are under ignored `.local/diagnostics/stockholm-awg/`. Only explicit probe results and route/resolver state are recorded; no packet capture or persistent client/server logging was enabled. Source `Daemon::logs()` returns no logs in this implementation, so repeatedly searching for daemon logs will not add evidence.
- Do not infer a fix from a reconnect: the initial guarded native trial passed 9/9 pings, three DNS/HTTPS/expected-exit checks and automatic recovery, with unchanged server/profile credentials. Route to the ping target used utun8/MTU1280, the AWG public endpoint stayed on en0, and DNS used 1.1.1.1/1.0.0.1. Earlier outage cause remains unconfirmed; longer reconnect evidence belongs in the launch record.
