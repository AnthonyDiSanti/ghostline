# Amnezia reference integration

Consult before retrying client/server installation. Sources: official [requirements](https://docs.amnezia.org/documentation/supported-linux-os-for-vps/), [setup](https://docs.amnezia.org/documentation/instructions/install-vpn-on-server/), [5.0.1.5 source](https://github.com/amnezia-vpn/amnezia-client/tree/5.0.1.5). Launch evidence lives in `docs/launch.md`.

- Ubuntu 24.04 x86_64 and passwordless-sudo `ubuntu` work with the installer. Select Manual → XRay; Automatic selects AmneziaWG.
- macOS 5.0.1.5 initially inherited `TMPDIR=/private/tmp/PKInstallSandbox.3VQHwF/tmp` when launched by the package installer. Server preparation created Docker, then local upload failed with ErrorCode 1200. Source `client/core/utils/selfhosted/sshSession.cpp` creates a QTemporaryFile for uploads; process environment exposed the stale installer directory. Quit and relaunch normally before retrying. Do not change directory permissions or bypass signing.
- CUA Qt accessibility labels are sparse; use screenshots to identify protocol cards and verify the resulting screen before starting installation.
- Paste SSH material into the secure field without printing it, then clear the clipboard. LastPass computer-use permission was denied; Anthony explicitly offered to intermediate all vault activity. Prepare local ignored artifacts and provide paths/item names.

- Actual XRay source `client/core/protocols/xrayProtocol.cpp` calls `StopRoutingIpv6` on connect and restores routing on stop. GUI exposes Soft KillSwitch, enabled in this setup; native IPv6 remains unverified because the tested network lacks successful IPv6-only resolution.
- SSH to the endpoint times out while the Mac tunnel is connected; disconnect before Amnezia server administration. Do not broaden the AWS SSH range to diagnose client routing.
- For a second region, generate a separate RSA4096 key with `ssh-keygen -m PEM`, and add a new self-hosted server through Manual → XRay. Keep the existing server/profile; IaC does not clone installer-managed runtime state. Use distinct names for recovery/device exports.
- If Qt's AX state changes but the screenshot remains on the previous page, raise the window using its exposed Raise action, then refresh AX/screenshot before choosing controls.

- Qt AX clicks on server radio buttons can change the displayed checkmark without applying the selected server. Click the visible server row, then verify the main screen’s endpoint IP and native egress. Switching requires disconnecting first.
- On macOS 5.0.1.5 the Connection export’s Share button opens a local Save dialog: `Pages2/PageShareConnection.qml` calls `getFileName(..., true)` then `ExportUiController::exportConfig` → `SystemController::saveFile` → `QFile`. Mobile branches differ. Source verification resolved an auto-review rejection of the ambiguous Share label; do not assume other Share controls are local exports.

- Fallback protocol research (2026-09-07): [AmneziaWG docs](https://docs.amnezia.org/documentation/amnezia-wg/) describe UDP transport and now include version 3.1, while some linked self-hosted instructions still refer to 2.0. Before adding a fallback, verify the installer and actual macOS/iOS client versions support the same protocol generation; do not select 2.0 from an older link title or assume profiles are interchangeable. [Current FAQ](https://docs.amnezia.org/faq/). Local UAE reachability remains untested for this candidate.
- Shared-host source inspection (5.0.1.5): `client/server_scripts/xray/run_container.sh` publishes the selected port on both TCP/UDP without a host-IP binding; `awg/run_container.sh` publishes UDP similarly. Both join `amnezia-dns-net`; AWG's `start.sh` masquerades tunnel traffic through eth0/eth1. Two EIPs alone will not yield isolated ingress/egress. See [architecture candidate](../../docs/architecture.md#selected-topology) before planning consolidation.
- Runtime extraction: tagged `server_scripts/xray/Dockerfile` pins Xray `v26.7.28` but downloads without a checksum check; AWG's Dockerfile uses `amneziavpn/amneziawg-go:latest`. Both upgrade packages and create a placeholder startup script for subsequent injection. Xray `start.sh` can reach `tail -f /dev/null` after daemon exit, while AWG configuration generates keys during setup. Our lifecycle must make process failure visible and preserve credentials on repeat deployment. Preserve source/license provenance when adapting recipes; upstream root README identifies GPLv3 and separate third-party terms.

## Owned runtime learnings (2026-09-07)

- The reference Xray directory has six flat files, including `server.json` with two clients and `clientsTable`. There is no running DNS sidecar or explicit server DNS config; preserve all bytes rather than regenerating a single-client template. The protected local bundle is `.local/recovery/cape-town-runtime.json`.
- Host Ubuntu and container Alpine versions are separate. Keep Ubuntu 24.04 and the inspected upstream container family during migration. Runtime pins and licensing are in `runtime/NOTICE.md`.
- This Ubuntu AMI already renders EC2 secondary IPv4 addresses in cloud-init netplan. Bootstrap verifies it; a redundant overlay was removed before cutover. DHCP provides the primary address/default route.
- Docker's `com.docker.network.host_ipv4` produced an actual kernel `SNAT --to-source` rule. Verified Xray container egress equals the existing EIP after reassociation. Inspect the rule and external IP, not just Compose text.
- AWG's userspace control socket is `/run/amneziawg/awg0.sock`, not `/run/wireguard`. The daemon advertises an old version string even though the pinned image's tools accept generated 3.1 settings. Disposable-container startup/restart tests verify the actual integration. Keep it unprivileged except TUN/NET_ADMIN.
- Docker Desktop's containerd image ID can be an index digest, while another host uses a different image identity representation. Transfer and reference a build-input-hash tag with pulling disabled; do not assume the local `.Id` is a portable remote image reference. ECR release management remains deferred.
- Secret diagnostics: catch JSON parser errors without quoting input; capture SSH/command output privately. Real server configuration should never reach tool output. Normal runtime logging stays disabled.
