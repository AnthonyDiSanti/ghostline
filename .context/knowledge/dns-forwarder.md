# Shared upstream DNS forwarder assessment — October 26, 2026

Decision update: CoreDNS is selected for one private shared resolver. Its authenticated DoT forwarding to Cloudflare then Google and local `.onion` NXDOMAIN are implemented, natively qualified in Ireland, published as schema v4 in four regions and live in Stockholm. Cape Town's observed state is in its launch record. [Current runtime contract](../../docs/dns.md). The earlier comparisons below record why the choice was made, not an open resolver selection.

The isolated Ireland trial already demonstrated ordinary port-53 interception from both AWG and REALITY, shared resolver delivery, certificate-checked Cloudflare DoT, controlled Google DoT fallback, and a host rule that drops plaintext DNS egress. Disposable encrypted clients reached ordinary HTTPS and DNS through both engines. Native iOS AWG and Mac OneXraySE sent ordinary DNS to the gateway, but that does not establish client-originated DoH or `.onion` hostname delivery. See [trial evidence](../scratch/2026-10-19-tor-retirement/tor-dns-trial.md#isolated-native-ireland-trial--october-12-2026).

## Shared egress identity — selected October 26

Anthony rejected a dedicated third public DNS address after reviewing its cost and blue-green quota impact. The shared private DNS container uses the host ENI's **primary private IPv4** for its allowed upstream traffic. In the present slots this is AWG's private address, mapped to the existing AWG EIP, but the DNS packets do not traverse AWG's container. Source-only policy now takes its DNS source from the same slot model that marks the ENI primary, so future protocol reassignment changes the DNS source with the host primary rather than with an AWG label. The deployed Ireland trial still uses the older REALITY-source image until a qualified replacement is released; historical counter observations below remain valid for that deployment.

This adds no IPv4 allocation, no EIP quota pressure, and no new listener. The rejected third-address alternative would cost [$0.005/hour for either an auto-assigned IPv4 or an EIP](https://aws.amazon.com/vpc/pricing/), and a symmetric three-address blue-green handoff would peak at six EIPs against the observed five-EIP quota in Stockholm and Cape Town. Auto-assignment to an arbitrary third private address is not part of the present [precreated-ENI layout](https://docs.aws.amazon.com/us_en/AWSEC2/latest/UserGuide/working-with-ip-addresses.html). No subnet, EIP or live instance was changed in this decision.

For an ordinary-DNS-only replacement, **CoreDNS is the provisional front-runner**, not a selected release. Its [forward plugin](https://coredns.io/plugins/forward/) supports full DNS message forwarding, DoT or DoH upstream, ordered `policy sequential`, per-upstream TLS names, and optional response-code failover. Test the exact configuration: Cloudflare `1.1.1.1` / `1.0.0.1` first, Google `8.8.8.8` / `8.8.4.4` second; authenticate each provider's TLS name; reject plaintext egress; and check timeout, SERVFAIL and total-outage behavior. Initially fall back on transport failure, not every SERVFAIL: a DNSSEC validation failure can also be SERVFAIL, and another provider may handle it differently. Explicitly set `failfast_all_unhealthy_upstreams`; the forward plugin otherwise tries a random upstream when all are marked unhealthy. A resolver process health check should not interpret an upstream outage as a reason to replace the whole gateway repeatedly.

**Unbound is the strongest alternative.** It offers a mature validating cache and DoT forwarding, but its usual server selection is not a strict primary/backup policy. Amnezia's current [dev DNS Dockerfile](https://github.com/amnezia-vpn/amnezia-client/blob/dev/client/server_scripts/dns/Dockerfile) uses Unbound with Cloudflare DoT, not CoreDNS. Do not copy its floating `latest` base or infer TLS-name authentication from the text: the source has a space before `#cloudflare-dns.com`, while [Unbound's configuration manual](https://unbound.docs.nlnetlabs.nl/en/latest/manpages/unbound.conf.html) requires the auth name attached to `forward-addr`. This is a source-level concern, not a tested claim about a deployed Amnezia image. DNSCrypt Proxy has broader encrypted-DNS features than required here; Xray's own DNS path does not cover AWG as a common wire resolver.

The remaining gate is candidate acceptance, not a new proof of the shared DNS architecture: build a pinned ARM64 image; remove onion mapping, virtual routing and HTTP sink; confirm full record types, TLS peer authentication, failover, plaintext denial, service health and both real-client ordinary browsing on the managed trial. The trial and retirement plan stay provisional until the independent DNS feature is chosen.

## Deeper comparison — October 26

| Ghostline criterion | CoreDNS | Unbound |
| --- | --- | --- |
| Cloudflare preferred, Google backup | `forward` supports `policy sequential` and separate TLS names per address. Transport failures automatically try another upstream; response-code failover is optional and needs a deliberate policy. Its all-unhealthy default is random retry unless fail-fast is configured. | A root `forward-zone` with four authenticated DoT addresses is straightforward, but Unbound normally selects forwarders by round-trip estimates, so Google may see queries while Cloudflare is healthy. `forward-first: yes` falls toward normal recursion rather than meaning Google backup; keep it `no`. |
| DNSSEC | The stock [`dnssec` plugin](https://coredns.io/plugins/dnssec/) signs served data; it is not a validating recursive resolver. Forwarding relies on the authenticated upstream's validation. | Built-in [validation](https://unbound.docs.nlnetlabs.nl/en/latest/getting-started/configuration.html) can independently check signed answers, with a managed root trust anchor. This is a real security advantage if provider-independent DNSSEC verification is desired; it adds trust-anchor lifecycle work. |
| Cache and outage policy | Optional [cache plugin](https://coredns.io/plugins/cache/) provides TTL caps, prefetch and optional stale answers; default SERVFAIL caching needs review. | Full validating cache, prefetch and optional [serve-expired](https://unbound.docs.nlnetlabs.nl/en/latest/topics/core/serve-stale.html). Both products should start without stale serving unless a deliberate availability policy calls for it. |
| Encrypted protocols | The [forward plugin](https://coredns.io/plugins/forward/) documents upstream DoT and DoH. The [server](https://coredns.io/manual/configuration/) also accepts downstream DoH/DoT with a certificate. | [DoT forwarding](https://unbound.docs.nlnetlabs.nl/en/latest/manpages/unbound.conf.html) and [downstream DoH](https://unbound.docs.nlnetlabs.nl/en/latest/topics/privacy/dns-over-https.html) are documented. A DoH listener in either server still requires client configuration and does not turn AWG's `DNS =` into DoH. |
| Container provenance and checks | CoreDNS publishes [official Linux ARM64 binaries and a minimal image](https://coredns.io/manual/what/). Its HTTP process-health endpoint is available, but a scratch image needs a packaged ECS probe client or another verified local health command. | Amnezia uses a community Unbound base image in its dev Dockerfile. For Ghostline, pin and qualify a specific ARM64 build and provide a local process/DNS health check. Independent DNSSEC needs a root trust-anchor update plan; automatic updates need a writable anchor path. |

Current weighting favors CoreDNS for a deliberately small forwarder, strict provider preference and existing Cloudflare/Google DoT policy. Unbound becomes preferable if independent DNSSEC validation and its resolver cache are product requirements, or if Cloudflare is merely favored rather than strictly first. Neither choice changes the proven shared-container packet path or solves client-side DoH by itself. The local trial has not benchmarked either candidate; this is a documentation/source comparison, not a release qualification.
